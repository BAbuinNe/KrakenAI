# Cross-Encoder + рейтинг поставщиков: реализация

## Что именно добавлено

1. `app/neural_reranker.py`: поиск и нейросетевое ранжирование **фрагментов КП** по каждому требованию ТЗ.
2. `app/main.py`: вызов поиска доказательств внутри `POST /api/analyses`. В JSON ответа появился `evidence_retrieval`.
3. `app/static/app.js`: раскрываемые фрагменты с цитатами, номерами строк и оценками релевантности. В интерфейсе прямо написано, какая технология использовалась.
4. `app/ranking.py`: при наличии весов оценочных пунктов в структурированном ТЗ создаётся отдельный взвешенный рейтинг по секциям (`tz_rubric`). Если в любой оцениваемой секции неизвестны факты, победитель не назначается. Для прочих ТЗ сохраняется общий режим весов 60/25/15.
5. `tests/test_neural_reranker.py`: проверки поиска, подключаемого Cross-Encoder (тестовая модель без скачивания), расчёта рейтинга и запрета допуска КП с нарушениями.

## Нейросетевой Cross-Encoder

**Вход:** пара строк `(требование ТЗ, фрагмент КП)`.

**Выход:** числовой raw relevance score. Это **не** оценка соответствия, не проценты и не вероятность правильного выбора. Сортируются фрагменты текста; решение о допуске принимает отдельная проверка. Для каждого требования сначала лексически отбираются максимум 8 кандидатов; Cross-Encoder переставляет их по оценке. На одну обработку ограничено максимум 48 групп требований.

Выбранная мультиязычная pretrained-модель: `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`.
Документация: https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1

Для включения локально:
```sh
pip install -r requirements-reranker.txt
EVIDENCE_RERANKER=cross_encoder
```
Для PowerShell:
```powershell
pip install -r requirements-reranker.txt
$env:EVIDENCE_RERANKER = "cross_encoder"
```

Модель загружается при первом запуске из Hugging Face, требует интернет, CPU/RAM и отдельного хранения весов; первый вызов может быть медленным. **Не включать по умолчанию на бесплатном Render** — зависимости PyTorch и весов модели могут превысить доступную память. По умолчанию работает `EVIDENCE_RERANKER=lexical`, который не является нейросетевой моделью. При отсутствии модели с `cross_encoder` результат явно показывает `mode=unavailable`, а не выдаёт лексический поиск за Cross-Encoder.

Обратите внимание: это один шаг *retrieve → re-rank*, пока без bi-encoder/векторной БД. На коротких документах этого достаточно для прототипа; на длинных — нужны чанкинг, индекс и замеры Recall@K.

## Итоговый рейтинг КП

**Отбор:** КП с хотя бы одним подтверждённым нарушением обязательного требования не попадает в рейтинг. Неизвестное обязательное требование тоже блокирует допуск до проверки.

**Если ТЗ содержит оценочные секции с весами:** для каждой секции из имеющихся PASS/FAIL формируется 0 (не выполнено), 5 (частично выполнено), 10 (выполнено полностью) и умножается на вес. Это принятое для пилота **упрощение**; реальная шкала, описанная в исходном ТЗ, должна быть подтверждена. Если любое значение UNKNOWN — итоговый победитель не назначается. Расчёт отмечен `tz_rubric`. Не менять формулу ТЗ произвольно.

**Если индивидуальная шкала отсутствует:** общий рейтинг с настраиваемыми весами соответствия, цены, срока и подтверждённой пользователем надёжности. Не найденная цена не выдумывается: критерий помечается недоступным, текущий общий режим перераспределяет веса между доступными критериями и предупреждает об этом. Это потенциальный методический риск, который следует учесть до эксплуатации.

## Метрики и реальные проверки

Cross-Encoder: `Recall@5` и `nDCG@5` на **размеченных человеком релевантных цитатах**. Проверка требования: `Macro-F1`, `Recall_FAIL`, ложные PASS. Поставщики: `nDCG@3` по экспертному ранжированию и `Top-1 agreement`.

Автоматические тесты проверяют свойства алгоритма, но **не доказывают ML-качество**. Для этого нужен датасет закупок, экспертная разметка и отдельный эксперимент.

## Не реализовано в текущем изменении

- Полная обработка всех нечисловых требований без участия человека.
- Гарантированное извлечение всего PDF/DOCX: существует лимит текста в парсере.
- Обученная модель ранжирования **самих поставщиков**; для поставщиков мы сознательно оставляем объяснимую формулу.
- Подтверждённое развёртывание Cross-Encoder на Render. Настройки, RAM и модель требуют отдельной проверки.
