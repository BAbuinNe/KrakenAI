# KrakenAI: архитектура анализа коммерческих предложений

## Подход
Не обучать большую языковую модель с нуля. Использовать настроенный через секреты хостинга OpenAI-compatible Chat Completions API и собственный воспроизводимый модуль проверки документов. Без AI_API_KEY система выполняет только числовые проверки.

1. Загрузить **одно ТЗ** и до **пяти КП** в PDF/DOCX/XLSX через защищённый API.
2. Проверить сигнатуру, размер и структуру файлов. Распознавание сканов (OCR) пока не реализовано.
3. Изолированным обработчиком извлечь текст и таблицы, сохранив источник и при последующей реализации — страницу / координаты.
4. Выделить требования: атрибут, единица измерения, оператор (минимум / максимум / равно), значение и обязательность.
5. Из каждого КП выделить соответствующие параметры. Использовать LLM для *предварительного* смыслового сопоставления с цитатами, никогда не заменяя им математическую валидацию.
6. Перевести единицы в нормализованную форму и проверить числа детерминированно. Статусы: pass, fail, unknown (отсутствие информации не является pass).
7. Для нечисловых условий отобразить предварительные наблюдения модели как potential_match / potential_mismatch / needs_review, требующие подтверждения специалиста.
8. Показать таблицу с оригинальными фрагментами документа и предоставить экспорт PDF/CSV/JSON.

## Разделение доверия
ТЗ и КП — недоверенный ввод. Prompt injection из документов не должен управлять приложением. LLM не получает серверные секреты, не выполняет SQL/команды и не назначает окончательные результаты. Математические сравнения и принятие итогового решения находятся вне модели.

## Следующий этап — продуктивный AI
- Настроить ключ провайдера через Render Environment (не через GitHub и не в браузере).
- Ввести JSON Schema для извлекаемых атрибутов и проверять её на сервере.
- Добавить OCR для сканов с разграничением ресурсов и лимитом обработки.
- Добавить точные ссылки на страницу, цитату и при возможности область страницы.
- Создать набор из 30–50 обезличенных ТЗ/КП с вручную размеченными правильными ответами, тестировать precision/recall извлечения и false-pass rate.
- Добавить очередь фоновых задач, Postgres, персистентные сессии, RBAC и аудит действий.
- Провести независимый тест безопасности перед работой с коммерческими секретами.

## Запуск
`docker compose up --build` для локальной установки. `render.yaml` — конфигурация пилотного Docker-развёртывания; при подключении репозитория необходимо установить уникальный APP_PASSWORD и при необходимости AI_MODEL / AI_API_KEY / AI_CHAT_COMPLETIONS_URL. Публичный сайт без API-ключа не является работающей нейросетью.
